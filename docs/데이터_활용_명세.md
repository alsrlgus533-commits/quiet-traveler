# 데이터 활용 명세

## 1. 필수 데이터 (제주데이터허브 OpenAPI 3종)

세 데이터 모두 `https://open.jejudatahub.net/api/proxy/{데이터키}/{프로젝트키}?…` 로 부르고, 응답은 `{"totCnt","hasMore","data":[…]}` 이다.
한 번에 100건까지만 주므로 `number`(쪽 번호)와 `limit=100` 으로 끝까지 넘겨 받는다. 받은 결과는 `agent/data/` 에 저장본으로 넣어 두어 키 없이도 실행된다.
갱신: `python -m agent.datahub` (와이파이·유동인구), `python -m agent.datahub --card` (카드).

### 1-1. 와이파이 AP그룹별 일일 사용량 — 최근 실제 붐빔

| 항목 | 내용 |
|---|---|
| 데이터키 | `1aa9D5DabtDt1at935b1tt5t1D95t5at` |
| 요청 변수 | `searchDate`(YYYYMMDD), `number`, `limit` |
| 응답 항목 | AP그룹명, 기준일, 업로드·다운로드 바이트, 세션 시간, 접속자 수(`userCount`) |
| 갱신 주기 | 매일 (약 3일 늦게 올라옴. 2026-11-18 기준 최신일 11-15) |
| 받은 범위 | 최근 35일 (2026-10-12 ~ 11-15), 하루 약 1,250개 AP그룹 |
| 저장 | `agent/data/datahub_wifi.json` — 앱 장소에 묶인 AP 의 날짜별 접속자 수와 제주 전체 합계만 저장 |
| 장소 연결 | AP그룹 이름이 장소를 직접 가리키는 것만 손으로 연결 (`agent/datahub.py` 의 `AP_MAP`, 37곳). 버스정류소·충전소 AP 는 뺐다 |
| 쓰는 곳 | 도구 `wifi_visitors` (장소별 날짜별 접속자, 최근 7일 ÷ 그 앞 기간 평균, 요일 지수), `place_forecast` 의 `recent_actual_wifi` |
| 처리 | 최근 7일 평균 ÷ 그 앞 4주 평균 → 1.2 이상 "요즘 평소보다 붐벼요", 0.8 이하 "한산해요". 요일 지수 = 그 요일 평균 ÷ 전체 평균 × 100. 그 장소 AP 가 하루 종일 안 잡힌 날은 뺀다 |
| 한계 | 공공와이파이에 접속한 사람만 세므로 방문객의 일부. AP 수가 장소마다 달라 **장소끼리 숫자를 견주지 않고** 같은 장소의 변화만 본다 |

### 1-2. 읍면동 단위 내국인 유동인구 — 지역·요일 패턴

| 항목 | 내용 |
|---|---|
| 데이터키 | `Daaa1t3at3tt8a8DD3t55538t35Dab1t` |
| 요청 변수 | `startDate`·`endDate`(필수, YYYYMMDD), `city`, `emd`, `gender`, `ageGroup`, `number`, `limit` |
| 응답 항목 | 기준일, 시, 읍면동, 성별, 연령대, 거주인구(`resdPop`), 직장인구(`workPop`), 방문인구(`visitPop`) |
| 갱신 주기 | 일 단위 자료, 공개가 2~3달 늦음 (2026-11-18 기준 최신일 08-31) |
| 받은 범위 | 가장 최근 8주 (2026-07-07 ~ 08-31), 43개 읍면동 × 성별·연령 |
| 저장 | `agent/data/datahub_population.json` — 날짜·읍면동별로 성별·연령을 더한 합계 |
| 장소 연결 | 조용한 곳은 주소의 읍·면, 유명한 곳은 손으로 맞춘 읍면동 (`EMD_OF`) |
| 쓰는 곳 | 도구 `area_visitors` (지역 요일 지수, 주민 대비 방문 비율, 방문 순위) |
| 한계 | 내국인만, 여름 성수기(7~8월) 기준. 날짜 예측이 아니라 **요일·지역 성향**의 근거로 쓴다 |

### 1-3. 관광지·상업지구 시간대별 카드 데이터 — 하루 중 시간대 비율

| 항목 | 내용 |
|---|---|
| 데이터키 | `DD7a1ta6tba70bt7tD1D1aDttDt701b7` |
| 요청 변수 | `startDate`, `endDate`(필수, YYYYMM), `districtType`(상업지·내국인 주요 관광지·중국인 주요 관광지·제주시 구도심·서귀포시 구도심), `userType`(내국인관광객·중국인관광객), `dateTimeCategory`(오전·점심·오후·저녁·밤) |
| 응답 항목 | 지구, 관광객 구분, 연월, 시간대, 이용자수, 이용횟수, 이용금액 |
| 받은 범위 | 5개 지구 × 관광객 2종 × 시간대 5개 = 50건 (API 가 값을 돌려주는 공개분) |
| 저장 | `agent/data/datahub_card_time.json` |
| 쓰는 곳 | 도구 `jeju_card_time_pattern` — 지구별 시간대 결제 비율(%), 가장 붐비는 시간대 |
| 한계 | 결제 시간대 비율이라 방문 인원과 다름. 오래된 공개분이라 절대량이 아닌 **시간대 비율 근거**로만 씀 |

이용조건: 제주데이터허브 공개 데이터, 프로젝트에 데이터를 추가하고 프로젝트 키로 이용. 키는 제출물에 넣지 않는다.

**제주빅데이터센터 데이터(계획):** 센터 데이터 프리존의 「내국인 카드 이용 현황」을 제주데이터허브로 신청해 센터 안에서 읍면동·요일별로 집계하고, 원본은 반출하지 않고 집계 결과만 도구에 연결할 계획이다. 제출 시점에는 연결하지 않았다.

| 단기예보·중기예보(육상·기온) | 기상청 API허브 | 활용신청 | 오늘~10일 날씨 |

| 시도 경계 2013 | 통계청 (southkorea/southkorea-maps 공개 저장소) | 공개 | 제주 해안선 지도(SVG) |

## 3. 처리와 분석 흐름

```
[수집]  fetch_forecast.py  ─ 관광공사 예측(제주시·서귀포시) + 기상청/Open-Meteo 날씨 → forecast.json
        agent/datahub.py   ─ 제주데이터허브 와이파이(35일)·유동인구(8주)·카드 → agent/data/datahub_*.json
        tools/export_places.mjs ─ 화면의 장소 53곳 → agent/data/places.json
[계산]  agent/core.py
        평소 대비 배율 = 그날 예측 집중률 ÷ 그 장소의 30일 평균 (0.5~1.8 로 제한; 예측 없는 곳은 제주 전체 평균 대비)
        붐빔 추정 = 100 × 장소 규모 × 유형별 시간대 곡선(h) × 평소 대비 배율 × 1.5 + 6  (최대 100)
        한산함 = 100 − 붐빔 추정 → 65 이상 한산해요 · 45~64 적당해요 · 45 미만 붐벼요 (주차: 여유·보통·혼잡)
        비 예보(비·소나기·눈·뇌우, 비 올 확률 40% 이상) → 오름 제외, 숲길 +12 · 마을 +8 · 바다 −25
        코스 = 빔 탐색(상위 300 경로): 머무는 동안 한산함 합 − 이동 분 × 0.5 + 테마 다양성
        최근 추세 = 장소 와이파이 접속자 최근 7일 평균 ÷ 그 앞 4주 평균 (1.2↑ 붐벼요 · 0.8↓ 한산해요)
        요일 지수 = 그 요일 평균 ÷ 전체 평균 × 100 (와이파이·유동인구)
[답]    agent/tools.py 의 도구 8개가 계산 결과를 JSON 으로 → 업스테이지 Solar 가 근거를 붙여 설명
```

## 4. 개인정보

- 사용하는 모든 데이터는 집계 통계(관광지별 예측, AP그룹별 하루 접속자 수, 읍면동별 인구 합계, 지구별 카드 이용 합계, 날씨)이며 개인을 알아볼 수 있는 정보가 없다.
- 대화 내용은 서버에 저장하지 않는다(브라우저 화면에만 남고 새로고침하면 사라짐). 질문은 답을 만들기 위해 업스테이지 API 로 전송된다.
- 저장 기능(♡)은 사용자 브라우저에만 저장된다.
