# 데이터 활용 명세

## 1. 필수 데이터 (제주데이터허브)

| 항목 | 내용 |
|---|---|
| 데이터명 | 관광지·상업지구 시간대별 카드 데이터 |
| 제공 | 제주데이터허브 (jejudatahub.net), OpenAPI |
| 호출 | `https://open.jejudatahub.net/api/proxy/DD7a1ta6tba70bt7tD1D1aDttDt701b7/{프로젝트키}?startDate=YYYYMM&endDate=YYYYMM&districtType=…` |
| 요청 변수 | `startDate`, `endDate`(필수, YYYYMM), `districtType`(상업지·내국인 주요 관광지·중국인 주요 관광지·제주시 구도심·서귀포시 구도심), `userType`(내국인관광객·중국인관광객), `dateTimeCategory`(오전·점심·오후·저녁·밤) |
| 응답 항목 | 지구, 관광객 구분, 연월, 시간대, 이용자수, 이용횟수, 이용금액 |
| 받은 범위 | 5개 지구 × 관광객 2종 × 시간대 5개 = 50건. API 가 실제로 값을 돌려준 달은 2017년 11월 (2017-12 ~ 2022 은 빈 응답) |
| 저장 | `agent/data/datahub_card_time.json` (키 없이도 실행되도록 저장본 포함). 갱신: `python -m agent.datahub` |
| 이용조건 | 제주데이터허브 공개 데이터, 프로젝트 키 발급 후 이용. 키는 제출물에 넣지 않음 |
| 쓰는 곳 | 도구 `jeju_card_time_pattern` — 지구별 시간대 결제 비율(%), 가장 붐비는 시간대, 가장 한산한 낮 시간대 |
| 처리 | 지구·관광객 구분별로 시간대 이용횟수를 더해 비율로 바꿈. 이용금액은 쓰지 않음 |
| 한계 | 결제가 일어난 시간대 비율이라 실제 방문 인원과 다름. 시간대 경계 정의 없음. 한 달치라 계절 차이 반영 못 함 → 절대량이 아닌 **시간대 비율 근거**로만 씀 |

**제주빅데이터센터 데이터(계획):** 센터 데이터 프리존의 「내국인 카드 이용 현황」을 제주데이터허브로 신청해 센터 안에서 읍면동·요일별로 집계하고, 원본은 반출하지 않고 집계 결과만 도구에 연결할 계획이다. 제출 시점에는 연결하지 않았다.

## 3. 처리와 분석 흐름

```
[수집]  fetch_forecast.py  ─ 관광공사 예측(제주시·서귀포시) + 기상청/Open-Meteo 날씨 → forecast.json
        agent/datahub.py   ─ 제주데이터허브 카드 시간대 데이터 → agent/data/datahub_card_time.json
        tools/export_places.mjs ─ 화면의 장소 53곳 → agent/data/places.json
[계산]  agent/core.py
        평소 대비 배율 = 그날 예측 집중률 ÷ 그 장소의 30일 평균 (0.5~1.8 로 제한; 예측 없는 곳은 제주 전체 평균 대비)
        붐빔 추정 = 100 × 장소 규모 × 유형별 시간대 곡선(h) × 평소 대비 배율 × 1.5 + 6  (최대 100)
        한산함 = 100 − 붐빔 추정 → 65 이상 한산해요 · 45~64 적당해요 · 45 미만 붐벼요 (주차: 여유·보통·혼잡)
        비 예보(비·소나기·눈·뇌우, 비 올 확률 40% 이상) → 오름 제외, 숲길 +12 · 마을 +8 · 바다 −25
        코스 = 빔 탐색(상위 300 경로): 머무는 동안 한산함 합 − 이동 분 × 0.5 + 테마 다양성
[답]    agent/tools.py 의 도구 6개가 계산 결과를 JSON 으로 → 업스테이지 Solar 가 근거를 붙여 설명
```

## 4. 개인정보

- 사용하는 모든 데이터는 집계 통계(관광지별 예측, 지구별 카드 이용 합계, 날씨)이며 개인을 알아볼 수 있는 정보가 없다.
- 대화 내용은 서버에 저장하지 않는다(브라우저 화면에만 남고 새로고침하면 사라짐). 질문은 답을 만들기 위해 업스테이지 API 로 전송된다.
- 저장 기능(♡)은 사용자 브라우저에만 저장된다.
